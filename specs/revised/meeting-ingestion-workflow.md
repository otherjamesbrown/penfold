# Meeting Ingestion Workflow - Manual First Approach

## Design Philosophy
**Focus on context over integrations**: Manual upload process for MVP to concentrate on core value of contextual archaeology rather than complex API integrations.

## Meeting Upload Workflow

### Step 1: Meeting Metadata Input
User provides basic context via CLI:
```bash
penfold meeting create
> Meeting title: Atlas Q1 Planning Review
> Date/time: 2025-01-15 14:00
> Duration: 60 minutes
> Attendees: james@company.com, bob@company.com, alice@company.com
> Projects (optional): Atlas, Q1 Planning
```

### Step 2: Content Upload Menu
System presents upload options:
```bash
Available content types:
[1] Personal notes (text/markdown)
[2] AI summary (from Zoom/Teams/etc.)
[3] Full transcript (text file)
[4] Shared documents/attachments
[5] Audio recording
[6] Video recording
[7] Done - process meeting

Select content type to upload (1-7):
```

### Step 3: File Upload and Processing
For each content type:
```bash
# Example: AI Summary upload
> Selected: AI summary
> File path: /path/to/zoom_summary.txt
> Additional context (optional): Generated by Zoom AI
> Processing... ✓
> Continue with more content? [y/n]
```

### Step 4: Project Assignment and Review
```bash
Meeting content processed:
- Personal notes: 250 words
- AI summary: 180 words
- Transcript: 2,400 words
- 2 attachments: presentation.pptx, requirements.docx

AI suggests projects: [Atlas: 95%] [Q1 Planning: 87%]
Accept suggestions? [y/n/edit]
```

## Content Type Handling

### Text Content (Notes, Summaries, Transcripts)
- Store full content for search and analysis
- Extract entities (people mentions, decisions, action items)
- Generate embeddings for vector search
- Link to metadata (meeting, attendees, date)

### Documents/Attachments
- Store metadata and file path/URL
- Extract text content where possible (PDF, DOCX)
- Link to meeting context
- Generate file summary for search

### Media Files (Audio/Video)
- Store file path and metadata
- Generate transcription (local Whisper model)
- Process transcript through normal text pipeline
- Maintain link to original media for playback

### Personal Notes
- Highest priority for processing (your direct insights)
- Often contains context not in official summaries
- May include private thoughts/reactions
- Link to official meeting content

## Storage Structure

### Meeting Entity
```
meeting_id: UUID
title: string
date_time: datetime
duration_minutes: int
attendees: [person_ids]
project_contexts: [project_ids]
created_at: datetime
```

### Meeting Content
```
content_id: UUID
meeting_id: UUID (foreign key)
content_type: enum (notes, summary, transcript, document, audio, video)
file_path: string (local storage path)
extracted_text: text (for search)
metadata: jsonb (file size, duration, source platform)
processed_at: datetime
```

## Processing Pipeline

### Real-time Processing (During Upload)
1. **Text Extraction**: OCR for PDFs, speech-to-text for audio/video
2. **Entity Recognition**: People, topics, action items
3. **Quick Categorization**: Project assignment suggestions
4. **Embedding Generation**: Multiple models for vector search

### Batch Processing (Nightly)
1. **Cross-Meeting Analysis**: Link related discussions over time
2. **Timeline Construction**: Build meeting sequences for projects
3. **Pattern Detection**: Recurring topics, participant networks
4. **Context Enhancement**: Link to related emails, documents

## CLI Interface Design

### Meeting Creation Command
```bash
penfold meeting create [--title "Meeting Title"] [--date "2025-01-15"] [--attendees "email1,email2"]
penfold meeting upload --meeting-id <uuid> --type summary --file path/to/file
penfold meeting upload --meeting-id <uuid> --type notes --text "My notes here"
penfold meeting review --meeting-id <uuid>  # Review AI categorization
```

### Search and Retrieval
```bash
penfold search "Atlas deployment" --type meeting --since "last month"
penfold meeting timeline --project Atlas --last quarter
penfold meeting show <meeting-id> --with-content
```

## MVP Benefits

### Advantages of Manual Approach
- **Focus on core value**: Context reconstruction over integration complexity
- **Data control**: Complete ownership of all content
- **Flexibility**: Handle any meeting platform or format
- **Privacy**: No API keys or cloud platform dependencies
- **Learning**: Understand usage patterns before automation

### Future Automation Path
Once manual workflow proves value:
- Zoom API for auto-download
- Calendar integration for metadata
- Email parsing for meeting follow-ups
- Slack integration for related discussions

## Success Metrics for Manual Workflow

### Usability Metrics
- **Upload time**: <5 minutes for typical meeting
- **Search accuracy**: Find specific meeting content in <15 seconds
- **Context reconstruction**: Complete meeting timeline for project reviews

### Adoption Metrics
- **Consistency**: Upload meetings within 24 hours of occurrence
- **Completeness**: Average content types per meeting
- **Query frequency**: Daily searches of meeting content

This manual-first approach lets us prove the contextual archaeology value before investing in complex integrations.
